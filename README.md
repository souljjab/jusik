# 주식 분석 어시스턴트

종목 검색 · 차트 · 재무/가치 분석 · 매수/매도 추천 신호 · 관심종목 · 백테스트를 제공하는 앱입니다.
PC 웹앱으로 먼저 만들고, 같은 코드를 Capacitor로 감싸 APK로 배포하는 것을 전제로 설계했습니다.
**추천 신호는 정해진 규칙으로 계산한 참고 정보이며 투자 권유가 아닙니다. 주문 기능은 없습니다(조회 전용).**

## 구조

```
shared/  분석 로직(지표·신호·단타 스캐너·예수금 계획·모의매매·백테스트). 순수 TypeScript
server/  데이터 수집(웹사이트) + 스캐너/스케줄러 + 저장(JSON·엑셀·구글 시트) + API(Fastify)
web/     React + Vite 화면(PWA 매니페스트 포함)
data/    실행 중 생성: state.json(상태), jusik.xlsx(엑셀)  — git에 올라가지 않음
```

## 실행

```bash
npm install
npm run dev              # 서버 :8787 + 웹 :5173 → http://localhost:5173
npm run check:sources -w server   # 내 PC에서 네이버/야후 수집이 되는지 확인(아래 참고)
npm test                 # 단위 테스트
```

- `PROVIDER=web`(기본): 네이버 금융(국내) + 야후 파이낸스(미국) **웹사이트**에서 읽어옵니다. 증권사 API는 쓰지 않습니다.
- `PROVIDER=mock`: 오프라인 데모용 샘플 데이터(화면에 "샘플 데이터" 표시, 일부 종목은 일부러 돌파 모양으로 만들어 둠).
- 설정은 `server/.env.example`을 `server/.env`로 복사해서 바꿉니다.

## 단타 자동 스캔 · 예수금 · 모의매매 · 자동 일지

「단타 추천」 화면의 동작입니다.

1. **계속 찾기:** 장이 열려 있는 동안(국내 09:00–15:30 KST, 미국 09:30–16:00 뉴욕, 서머타임 자동 반영) 설정한 주기(기본 10분)로 시장별 거래대금 상위·상승률 상위 종목을 읽고 조건에 맞는 단타 후보를 찾습니다. 장이 닫혀 있으면 「지금 스캔」으로 마지막 종가 기준으로 돌려볼 수 있습니다. 공휴일은 알지 못합니다.
2. **단타 규칙(`shared/src/daytrade.ts`):** 거래량이 20일 평균의 1.2배↑(가점: 2·3·5배), 직전 20일 고점 돌파, 5>20일선 정배열, 고가 부근 마감(양봉), 당일 +2~20%(상한가 근처 추격 제외), RSI 80↑·20일선 25%↑ 이격 제외, 최소 거래대금·주가, 시장 국면 약세면 감점. 점수가 기준(기본 55) 이상이면 후보. 손절폭은 1.5×ATR을 2~5%로 제한, 목표는 손익비 2:1, 최대 보유 3거래일. **경험칙이며 수익이 검증된 규칙이 아닙니다.**
3. **예수금 기반 계획:** 국내(원)·해외(달러) 예수금을 따로 설정합니다. 점수 순으로 ① 손절 시 손실이 예수금의 N%(기본 1%) 이하 ② 종목당 최대 비중(기본 30%) ③ 예비 현금(기본 10%) ④ 최대 종목 수(기본 3)를 지키며 살 수 있는 수량을 계산하고, 못 사는 후보는 이유와 함께 보여줍니다.
4. **모의매매(선택):** 켜면 진입 가능 시간(개장 10분 후~마감 90분 전 근처)에 계획대로 가상 체결하고, 손절·목표·보유기간 조건을 보유 종목 점검 주기(기본 60초)마다 확인해 가상 청산합니다. 수수료·세금·슬리피지 0.1%를 반영하고, **매수·매도 이유와 순손익이 매매일지에 자동으로 기록**됩니다. **실제 주문은 하지 않습니다.** 직접 매매한 내용은 「매매일지」에서 수동으로 적습니다.
5. **저장:** 모든 상태는 `data/state.json`에, 같은 내용이 `data/jusik.xlsx`(요약·추천(최신)·추천이력·모의포지션·매매일지·성과 탭)에 저장됩니다(1차). 구글 시트가 설정되어 있으면 같은 탭 구성으로 덮어써 동기화합니다(2차).

비용 가정: 국내 수수료 0.015%×2 + 매도 거래세 0.18%, 미국 수수료 0.25%×2(증권사마다 다름) + SEC 수수료 약 0.003%. 실제 계좌의 수수료에 맞게 `shared/src/paper.ts`·`daytrade.ts`를 조정하세요.

### 데이터 출처 (웹 수집)

| 용도 | 국내 | 미국 |
|---|---|---|
| 일봉·지수 | 네이버 `fchart.stock.naver.com` | 야후 `query1.finance.yahoo.com/v8/finance/chart` |
| 후보 풀 | 네이버 거래량·상승률 상위 표 | 야후 스크리너(day_gainers, most_actives) |

| 재무 | 네이버 종목 메인 '기업실적분석' | 야후 quoteSummary(crumb 필요) |

**꼭 알아둘 것**
- **이 코드는 실제 사이트에 접속해 검증하지 못했습니다.** 개발 환경의 네트워크가 해당 사이트를 막고 있어서, 응답 형식은 제가 아는 형태를 흉내 낸 샘플로만 테스트했습니다. 처음 쓸 때 **`npm run check:sources -w server`를 실행**해 항목별 성공/실패를 확인하세요. 실패하면 `server/src/naver.ts`·`yahoo.ts`의 파서를 사이트 응답에 맞게 고쳐야 합니다(파서마다 테스트가 있어 고치기 쉽게 해 두었습니다).
- 이 사이트들은 공식 API가 아니라 웹페이지/비공식 주소를 읽는 방식이라 **예고 없이 바뀌거나 막힐 수 있고, 이용약관이 자동 수집을 제한할 수 있습니다.** robots.txt와 약관은 확인하지 못했으니 직접 확인하세요. 코드는 개인 용도·낮은 빈도(요청 직렬 처리, 기본 0.5초 간격, 429/5xx 시 백오프)로만 읽도록 만들었고, 간격을 줄이지 않는 것을 권장합니다.
- 야후 지수·S&P500은 `^GSPC`를, 네이버 지수는 `KOSPI`/`KOSDAQ` 심볼을 가정했습니다(지수 값의 배율은 분석에 영향이 없습니다).
- 증권사 API(KIS) 연동 코드는 이번에 제거했습니다(git 기록에 남아 있음).

### 구글 스프레드시트(2차 저장) 설정

1. Google Cloud에서 서비스 계정 생성 → Google Sheets API 사용 설정 → JSON 키 다운로드
2. 대상 스프레드시트를 서비스 계정 이메일에 **편집자**로 공유
3. `server/.env`에 `GOOGLE_SHEET_ID`(주소의 `/d/` 뒤 값), `GOOGLE_SERVICE_ACCOUNT_FILE`(키 파일 경로) 입력 — 키 파일은 저장소에 커밋하지 마세요

탭이 없으면 만들고, 있으면 내용을 지우고 다시 씁니다(값은 RAW라 `=`로 시작해도 수식으로 실행되지 않음). 이 부분은 가짜 서버로 요청 순서만 테스트했고 실제 구글 계정으로는 확인하지 못했습니다.

## 분석 로직 (4단계 파이프라인)

도서 12권 분석 PDF의 공통 구조인 **시장 국면 → 종목 스크리닝 → 진입·청산 → 리스크·복기** 순서로 구성했습니다.
`shared/src/analyze.ts`가 1~3단계를 묶어 최종 의견을 내고, 4단계는 `risk.ts`와 매매일지가 맡습니다.

| 단계 | 하는 일 | 근거(PDF의 책) | 코드 |
|---|---|---|---|
| ① 시장 국면 | 지수(코스피/코스닥) 주봉을 4단계로 판정 → 강세/중립/약세. **약세면 신규 매수 보류**, 지수 RSI 75↑는 과열 경고 | 와인스타인(30주선), 살 때·팔 때·벌 때(시장 먼저) | `regime.ts` |
| ② 종목 스크리닝 | 부채비율≤150%, 유동비율≥100%, 유보율≥200%, 0<PER≤10, PBR≤1, 매출·영업이익 증가율>0 체크리스트 → A~D 등급. **데이터 없는 항목은 감점하지 않고 제외**. D등급이면 매수 신호를 한 단계 낮춤 | 주린이도 수익 내는 알짜 주식 선정 노하우 9가지 | `screening.ts` |
| ③ 진입·청산 | 주봉 30주선·기울기로 1~4단계 판정. 2단계 + 돌파(직전 20주 고점, 거래량 2배↑) + 상대강도>0이면 강력 매수, 30주선에서 25%↑ 벌어지면 추격 금지, 4단계는 매수 금지. 손절가 = 최근 8주 저점. 캔들(망치·장악·샛별 등)은 보조 신호 | 와인스타인, 캔들마스터 | `stage.ts`, `candles.ts` |
| ④ 리스크·복기 | 손절폭 기준 수량 계산(1회 손실 ≤ 자본의 N%, 종목 비중 상한), 기대값·켈리, 매매일지(FIFO 손익·승률·CSV) | 새로운 시장의 마법사들, 원칙을 지키는 주식 고수들 | `risk.ts`, `journal.ts` |

**투자 기간:** 주봉 기준 중기(수 주~수 개월)로 잡았습니다. 책마다 단타·장기 올인·분산이 충돌해서, 한 종목 몰빵 대신 **손절폭 기준 비중 + 비중 상한(기본 25%)**을 기본값으로 했습니다.

**백테스트 두 가지:** 주봉 단계 전략(기본)과 일봉 점수 전략(`technical.ts`, 단기·비교용). 둘 다 신호 다음 거래일 시가에 체결하고 수수료 0.015% + 매도세 0.18%를 반영합니다.
주봉 전략은 주가 마감된 뒤에만 신호를 바꾸고, 손절가는 올리기만 합니다. 재무 스크리닝은 과거 시점 재무 데이터가 없어 백테스트에서 제외됩니다.

### 한계 — 꼭 읽어 주세요

- **규칙은 책의 요약본(PDF)을 제가 해석해 옮긴 것입니다.** 원서의 세부 규칙과 다를 수 있고, 기준값(PER 10 이하 등)은 저자 경험치이지 검증된 통계가 아닙니다.
- **수익이 검증되지 않았습니다.** 샘플(무작위) 데이터 39종목에서 주봉 전략 평균 -4.2%, 단순 보유 평균 +1.0%, 단순 보유를 이긴 종목 18/39였습니다. 무작위 데이터라 규칙이 이길 이유가 없으니 당연한 결과이고, 실제 시장에 대한 증거는 아닙니다. **KIS 실데이터로 여러 종목·긴 기간을 백테스트해서 확인하기 전에는 매매 근거로 쓰지 마세요.**
- 시장 국면은 **지수 추세만** 사용합니다. 금리·수익률곡선·M2·VIX·CAPE 같은 매크로 지표는 데이터 소스가 없어 미반영입니다.
- 업종 평균 PER/PBR 비교, 수급(외국인·기관), 뉴스, 지분 구조는 미반영입니다(스크리닝에서 "데이터 없음").
- 적립식 분할매수(적금주식) 시뮬레이터와 실시간(웹소켓) 시세는 없습니다. 단타 스캐너는 일봉 기준이라 분봉 신호는 보지 않고, 모의매매는 폴링한 현재가로 체결을 가정하므로 손절가를 갭으로 건너뛰는 상황은 실제보다 낙관적일 수 있습니다.
- 단타 규칙은 백테스트하지 않았습니다(과거 순위표 데이터가 없음). 대신 모의매매 결과를 매매일지에 쌓아 검증하세요.
- 매매일지·설정·모의계좌는 `data/state.json`(서버)에 저장됩니다. 파일을 지우면 사라지니 엑셀/구글 시트로도 보관하세요. 관심종목만 브라우저에 저장됩니다.
- 종목 추천을 **서비스로 공개**하면 국내에서 투자자문업·유사투자자문업 규제 대상일 수 있습니다. 공개 전에 따로 확인하세요(개인 학습용·조건 검색·복기 도구로 쓰는 것은 부담이 적습니다).

## APK로 배포하기 (다음 단계)

APK에서는 `localhost`의 서버를 쓸 수 없으므로 **서버를 어딘가에 배포**해야 합니다(키는 서버에만 둡니다).

```bash
# 1) 서버를 배포한 뒤 그 주소로 웹을 빌드
VITE_API_BASE=https://your-server.example.com npm run build

# 2) Capacitor로 Android 프로젝트 생성
cd web
npm i @capacitor/core @capacitor/cli @capacitor/android
npx cap init jusik com.example.jusik --web-dir=dist
npx cap add android && npx cap sync android
npx cap open android      # Android Studio에서 APK/AAB 빌드
```

서버에 CORS 허용 도메인을 제한하고(`server/src/app.ts`), 가능하면 간단한 인증을 붙이세요.
