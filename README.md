# 주식 분석 어시스턴트

종목 검색 · 차트 · 재무/가치 분석 · 매수/매도 추천 신호 · 관심종목 · 백테스트를 제공하는 앱입니다.
PC 웹앱으로 먼저 만들고, 같은 코드를 Capacitor로 감싸 APK로 배포하는 것을 전제로 설계했습니다.
**추천 신호는 정해진 규칙으로 계산한 참고 정보이며 투자 권유가 아닙니다. 주문 기능은 없습니다(조회 전용).**

## 구조

```
shared/  분석 로직(지표·신호·가치평가·백테스트). 순수 TypeScript — 웹/서버/APK가 함께 사용
server/  시세 프록시 API(Fastify). 증권사 앱키를 클라이언트에 노출하지 않기 위해 필요
web/     React + Vite 화면(PWA 매니페스트 포함)
```

## 실행

```bash
npm install
npm run dev        # 서버 :8787 + 웹 :5173 동시 실행 → http://localhost:5173
npm test           # 단위 테스트
npm run typecheck
npm run build      # web/dist 생성
```

기본값은 **샘플 데이터**(가짜 시세, 화면에 "샘플 데이터" 표시)라 키 없이 바로 실행됩니다.

## 한국투자증권 API 연동

1. https://apiportal.koreainvestment.com 에서 앱키/시크릿 발급
2. `server/.env.example` → `server/.env` 복사 후 입력
   ```
   PROVIDER=kis
   KIS_APP_KEY=...
   KIS_APP_SECRET=...
   KIS_BASE_URL=https://openapi.koreainvestment.com:9443   # 모의투자는 https://openapivts.koreainvestment.com:29443
   ```
3. `npm run dev`

`.env`와 `.kis-token.json`은 `.gitignore`에 들어 있습니다. 키는 절대 커밋하지 마세요.

> **키움증권 OpenAPI+는 쓸 수 없습니다.** Windows 전용 OCX(COM)라서 웹/APK 구조와 맞지 않습니다.
> REST 방식인 한국투자증권(KIS)을 사용합니다. 다른 증권사를 쓰려면 `server/src/provider.ts` 인터페이스를 구현하면 됩니다.

**검증 상태:** KIS 제공자는 응답 형식을 가짜 `fetch`로 흉내 낸 단위 테스트(토큰 발급·재발급, 100봉 단위 페이지 조회, 지수 조회, 오류 처리)까지만 확인했습니다.
실제 계정으로는 아직 호출해 보지 않았으므로, 처음 연동할 때 필드명을 확인해야 합니다. 특히 **지수 일봉(`inquire-daily-indexchartprice`, `bstp_nmix_*`)**, **`finance/financial-ratio`(성장률·부채비율·유보율)**, **`finance/stability-ratio`(유동비율)**는 기억에 의존해 작성한 부분이라 응답과 다르면 `server/src/kis.ts`를 고쳐야 합니다. 재무 항목은 실패해도 해당 항목만 "데이터 없음"이 됩니다.
종목명 검색은 증권사 API에 없어서 `server/src/stocks.ts`의 내장 목록(40종목)을 씁니다. 전체 종목이 필요하면 KRX 종목 마스터로 교체하세요.

## 분석 로직 (4단계 파이프라인)

도서 12권 분석 PDF의 공통 구조인 **시장 국면 → 종목 스크리닝 → 진입·청산 → 리스크·복기** 순서로 구성했습니다.
`shared/src/analyze.ts`가 1~3단계를 묶어 최종 의견을 내고, 4단계는 `risk.ts`와 매매일지가 맡습니다.

| 단계 | 하는 일 | 근거(PDF의 책) | 코드 |
|---|---|---|---|
| ① 시장 국면 | 지수(코스피/코스닥) 주봉을 4단계로 판정 → 강세/중립/약세. **약세면 신규 매수 보류**, 지수 RSI 75↑는 과열 경고 | 와인스타인(30주선), 살 때·팔 때·벌 때(시장 먼저) | `regime.ts` |
| ② 종목 스크리닝 | 부채비율≤150%, 유동비율≥100%, 유보율≥200%, 0<PER≤10, PBR≤1, 매출·영업이익 증가율>0 체크리스트 → A~D 등급. **데이터 없는 항목은 감점하지 않고 제외**. D등급이면 매수 신호를 한 단계 낮춤 | 주린이도 수익 내는 알짜 주식 선정 노하우 9가지 | `screening.ts` |
| ③ 진입·청산 | 주봉 30주선·기울기로 1~4단계 판정. 2단계 + 돌파(직전 20주 고점, 거래량 2배↑) + 상대강도>0이면 강력 매수, 30주선에서 25%↑ 벌어지면 추격 금지, 4단계는 매수 금지. 손절가 = 최근 8주 저점. 캔들(망치·장악·샛별 등)은 보조 신호 | 와인스타인, 캔들마스터 | `stage.ts`, `candles.ts` |
| ④ 리스크·복기 | 손절폭 기준 수량 계산(1회 손실 ≤ 자본의 N%, 종목 비중 상한), 기대값·켈리, 매매일지(FIFO 손익·승률·CSV) | 새로운 시장의 마법사들, 원칙을 지키는 주식 고수들 | `risk.ts`, `journal.ts` |

**투자 기간:** 주봉 기준 중기(수 주~수 개월)로 잡았습니다. 책마다 단타·장기 올인·분산이 충돌해서, 한 종목 몰빵 대신 **손절폭 기준 비중 + 비중 상한(기본 25%)**을 기본값으로 했습니다.

**백테스트 두 가지:** 주봉 단계 전략(기본)과 일봉 점수 전략(`technical.ts`, 단기·비교용). 둘 다 신호 다음 거래일 시가에 체결하고 수수료 0.015% + 매도세 0.18%를 반영합니다.
주봉 전략은 주가 마감된 뒤에만 신호를 바꾸고, 손절가는 올리기만 합니다. 재무 스크리닝은 과거 시점 재무 데이터가 없어 백테스트에서 제외됩니다.

### 한계 — 꼭 읽어 주세요

- **규칙은 책의 요약본(PDF)을 제가 해석해 옮긴 것입니다.** 원서의 세부 규칙과 다를 수 있고, 기준값(PER 10 이하 등)은 저자 경험치이지 검증된 통계가 아닙니다.
- **수익이 검증되지 않았습니다.** 샘플(무작위) 데이터 39종목에서 주봉 전략 평균 -4.2%, 단순 보유 평균 +1.0%, 단순 보유를 이긴 종목 18/39였습니다. 무작위 데이터라 규칙이 이길 이유가 없으니 당연한 결과이고, 실제 시장에 대한 증거는 아닙니다. **KIS 실데이터로 여러 종목·긴 기간을 백테스트해서 확인하기 전에는 매매 근거로 쓰지 마세요.**
- 시장 국면은 **지수 추세만** 사용합니다. 금리·수익률곡선·M2·VIX·CAPE 같은 매크로 지표는 데이터 소스가 없어 미반영입니다.
- 업종 평균 PER/PBR 비교, 수급(외국인·기관), 뉴스, 지분 구조는 미반영입니다(스크리닝에서 "데이터 없음").
- 적립식 분할매수(적금주식) 시뮬레이터, 미국 주식, 실시간(웹소켓) 시세는 아직 없습니다.
- 매매일지는 브라우저(localStorage)에만 저장됩니다. 브라우저 데이터를 지우면 사라지니 CSV로 내보내 두세요.
- 종목 추천을 **서비스로 공개**하면 국내에서 투자자문업·유사투자자문업 규제 대상일 수 있습니다. 공개 전에 따로 확인하세요(개인 학습용·조건 검색·복기 도구로 쓰는 것은 부담이 적습니다).

## APK로 배포하기 (다음 단계)

APK에서는 `localhost`의 서버를 쓸 수 없으므로 **서버를 어딘가에 배포**해야 합니다(키는 서버에만 둡니다).

```bash
# 1) 서버를 배포한 뒤 그 주소로 웹을 빌드
VITE_API_BASE=https://your-server.example.com npm run build

# 2) Capacitor로 Android 프로젝트 생성
cd web
npm i @capacitor/core @capacitor/cli @capacitor/android
npx cap init jusik com.example.jusik --web-dir=dist
npx cap add android && npx cap sync android
npx cap open android      # Android Studio에서 APK/AAB 빌드
```

서버에 CORS 허용 도메인을 제한하고(`server/src/app.ts`), 가능하면 간단한 인증을 붙이세요.
